# ЕшьКуш — автономная демонстрация

Готовый сценарий показа сервиса: покупатель выбирает и оплачивает бокс, партнёр получает заказ и отмечает выдачу, покупатель видит новый статус. Платежи, соцсети и поддержка имитируются локально. API-ключи, Telegram-бот, SMS и аккаунты внешних провайдеров не нужны.

## Запуск

Нужен работающий Docker Desktop с Linux containers.

```sh
docker compose -f compose.demo.yml up --build -d --wait
```

Или в Windows: `powershell -ExecutionPolicy Bypass -File scripts/Start-Demo.ps1`.

Откройте **http://127.0.0.1:8080/shop**. Первый запуск скачивает образы и пакеты; последующие используют локальный кеш. Картинки, иконки и шрифт хранятся локально. Интерактивная карта загружает тайлы OpenStreetMap через интернет; регистрация и API-ключи не нужны.

| Экран | Адрес |
|---|---|
| О сервисе | http://127.0.0.1:8080/about |
| Приложение покупателя | http://127.0.0.1:8080/shop |
| Кабинет партнёра | http://127.0.0.1:8080/login → «Открыть кабинет» |

## Что можно показать

- Наполненный каталог: 63 предложения, 30 точек заведений Тюмени; поиск, категории, смена города, карточка бокса и отзывы.
- Избранные заведения с сохранением в БД.
- Корзина с количеством, остатками и подсчётом экономии. Боксы разных заведений оформляются отдельными заказами, оплачиваются все.
- Демо-оплата картой или СБП без реквизитов, переход к коду получения и истории заказов.
- Кабинет партнёра: предложения, остатки, новые заказы, выдача и аналитика.
- Отмена и возврат: статус меняется, остаток возвращается; повторный возврат не увеличивает остаток снова.
- Интерактивная карта OpenStreetMap: 30 точек, поиск, категории, цены на метках, фотографии и карточки заведений, профиль с показателями экономии, уведомления по заказам и локальный помощник.
- Яндекс, ВКонтакте, Telegram и телефон в окне способов входа открывают фиксированный тестовый профиль без внешних запросов.
- Роли покупателя, партнёра и администратора остаются в API. Старый маршрут `/demo` перенаправляет в каталог; технические сведения и сброс убраны из публичного интерфейса.

## Сценарий на 3–5 минут

1. Откройте `/shop`, найдите заведение на карте или бокс в каталоге и добавьте его в корзину.
2. Выберите второй бокс из другого заведения. Перейдите к оформлению и подтвердите оплату картой или СБП.
3. Покажите «Мои заказы» и коды получения.
4. Откройте `/login` в другой вкладке → «Открыть кабинет» → «Заказы».
5. У нового заказа нажмите «Готов к выдаче», затем «Выдан». Приложение покупателя обновляет состояние каждые 8 секунд.
6. Второй заказ отмените через приложение покупателя. Покажите восстановленный остаток и состояние возврата.
7. Покажите избранное, отзыв, карту и кабинет с аналитикой.

В демо-режиме можно также войти вручную: `demo / Demo@1234`, `partner1 / Partner@1234`, `adminuser / Admin@1234`. Это публичные тестовые аккаунты только для демонстрации.

## Данные и интеграции

Стек: локальная PostgreSQL, Dart API и Nuxt web-приложение за Nginx. Для демонстрации используется отдельный Compose-проект `eshkush-demo` и отдельный том `demo_data`. Обычная конфигурация `docker-compose.yml` не затрагивается.

Перезапуск сохраняет заказы, остатки, избранное и отзывы. Начальная загрузка выполняется только для пустого каталога. Для нового показа используйте «Восстановить демо-данные» на `/demo`: эта операция удаляет изменения каталога и заказов демонстрации.

`DEMO_MODE=true` — явный серверный переключатель: включает тестовые сессии и принудительно локальную оплату, даже если в окружении есть ключи платёжного провайдера. При выключенном переключателе demo API недоступен. Compose открывает web только на loopback `127.0.0.1`, PostgreSQL и API не публикуются на хост.

Этот сценарий показа использует новое адаптивное web-приложение внутри `partner-web`. Flutter-клиент сохранён; сборка APK/IPA не входит в этот запуск.

## Проверка и разработка

```sh
python scripts/demo_smoke.py http://127.0.0.1:8080
docker compose -f compose.demo.yml ps
docker compose -f compose.demo.yml logs --tail 50
```

Smoke-тест проходит реальный путь через локальный HTTP API: роли, каталог и медиа, избранное, заказ из другой точки, два заказа из разных заведений, оплата, повтор оплаты, возврат, восстановление остатков, выдача партнёром, отзыв, refresh и logout. Тест создаёт два заказа в демонстрационных данных.

Изменили исходники — пересоберите: `docker compose -f compose.demo.yml up --build -d --wait`.

Для web-разработки отдельно: запустите backend через Compose, затем в `partner-web` выполните `npm ci`, задайте `NUXT_PUBLIC_API_BASE=http://127.0.0.1:8080/api` и `NUXT_PUBLIC_DEMO_MODE=true`, запустите `npm run dev`. Порт dev-сервера — 3010.

Остановка с сохранением данных: `docker compose -f compose.demo.yml down`.

## Каталог Тюмени и фотографии

`backend/public/demo/catalog/tyumen.json` содержит 30 точек: реальные названия, адреса, координаты и ссылки на источники. `photos.json` хранит происхождение локальных фотографий. Фото заведений взяты с официальных сайтов и из карточек Яндекс Карт; несколько филиалов используют фото своей сети. Фотографии еды иллюстрируют категории предложений, ассортимент и цены сгенерированы для показа. Брендинг использует маскот и иконку пакета из Flutter-проекта. Отдельного файла фирменного текстового логотипа в репозитории нет; название набрано шрифтом Stolzl из проекта.

Обновление существующей локальной базы без удаления заказов и отзывов:

```sh
docker compose -f compose.demo.yml exec -T -e DEMO_CATALOG_UPGRADE=true backend /app/seed-demo
```

Повторный запуск обновления сохраняет цены, остатки, пользовательские фото товаров и заказы, не дублирует точки или товары. На новой базе каталог загружается автоматически. Обычный перезапуск сохраняет изменения партнёра. Для полного восстановления исходных примеров используйте `DEMO_RESET=true` при запуске `/app/seed-demo`; это удаляет прежние точки, товары, заказы и отзывы локальной демонстрации.

Интерфейс проверяется по адресу `/shop`; на карте должна быть надпись «30 мест · Тюмень». Откройте метку, посмотрите фото и перейдите к боксам конкретного филиала.
