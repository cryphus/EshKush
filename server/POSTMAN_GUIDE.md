# 📋 Руководство по тестированию API в Postman

## 🚀 Быстрый старт

### 1. Импорт коллекции
1. Откройте **Postman**
2. Нажмите **Import** (Импорт)
3. Выберите один из файлов:
   - `EshKush_API_Postman_Collection.json` - базовая коллекция (основные endpoints)
   - `EshKush_API_Complete_Postman_Collection.json` - **ПОЛНАЯ коллекция (100+ endpoints)**
4. Коллекция будет добавлена в Postman

### 📋 Доступные коллекции

#### Базовая коллекция (EshKush_API_Postman_Collection.json)
- Аутентификация (регистрация, логин, refresh)
- Основные CRUD операции (точки, продукты, заказы)
- Кеш endpoints
- **Итого: ~20 endpoints**

#### Полная коллекция (EshKush_API_Complete_Postman_Collection.json) ⭐
- **Все вышеперечисленное +**
- Профили пользователей
- Партнеры
- Города
- Уведомления
- Промокоды
- Сессии пользователей
- Избранное
- Платежные транзакции
- **Итого: 100+ endpoints**

### 2. Настройка переменных
В коллекции уже настроены переменные:
- `base_url`: `http://localhost:8080`
- `access_token`: (будет заполнен автоматически после логина/регистрации)
- `refresh_token`: (будет заполнен автоматически после логина/регистрации)

### 🔑 Автоматическое управление токенами
Коллекция настроена для **автоматического сохранения токенов**:
- После успешной **регистрации** или **логина** токены автоматически сохраняются
- Все защищенные endpoints используют `{{access_token}}`
- При истечении токена используйте **"Обновление токена"** для получения нового

### 3. Запуск сервисов
Убедитесь, что все сервисы запущены:
```bash
docker-compose up -d
```

## 🔐 Тестирование аутентификации

### Шаг 1: Регистрация пользователя
1. Откройте запрос **"Регистрация пользователя"**
2. Измените данные в Body (email, username, number, role)
3. Нажмите **Send**
4. ✅ **Токены автоматически сохранятся** в переменные `{{access_token}}` и `{{refresh_token}}`
5. Проверьте консоль Postman - увидите сообщения о сохранении токенов

### Шаг 2: Логин пользователя
1. Откройте запрос **"Логин пользователя"**
2. Используйте те же username/password что и при регистрации
3. Нажмите **Send**
4. ✅ **Токены автоматически обновятся** в переменных
5. Проверьте консоль Postman - увидите сообщения о сохранении токенов

### 🔍 Проверка токенов
Чтобы убедиться, что токены работают:
1. Откройте любой защищенный endpoint (например, **"Получить профиль"**)
2. Нажмите **Send**
3. Если получили данные пользователя - токены работают! ✅
4. Если получили ошибку 401 - используйте **"Обновление токена"**

### 🔄 Обновление токенов
Если токен истек:
1. Откройте запрос **"Обновление токена"**
2. Нажмите **Send**
3. ✅ Новый токен автоматически сохранится

## 📍 Тестирование основных endpoints

### ⚠️ Важные замечания по обязательным полям

При создании сущностей обратите внимание на обязательные поля:

#### **Создание точки:**
- `name`, `address`, `latitude`, `longitude` - **обязательны**
- `opening_hours` и `closing_hours` - **обязательны** (формат: "09:00", "18:00")
- `partner_id` и `city_id` - должны существовать в базе
- ❌ `description` - НЕ обязательное поле

#### **Создание партнера:**
- `user_id`, `name`, `contact_person`, `contact_email`, `contact_phone`, `contact_document` - **обязательны**
- `contact_person` - строка (имя), НЕ ID пользователя
- `max_discount` - необязательное (по умолчанию 0.0)

#### **Создание продукта:**
- `name`, `description`, `price`, `point_id`, `partner_id`, `weight` - **обязательны**
- ❌ `category_ids` - НЕ обязательное поле

#### **Создание заказа:**
- `user_id`, `point_id`, `products_id`, `date`, `total_price` - **обязательны**
- `date` - формат ISO: "2024-01-15T10:30:00Z"
- ❌ `status` - НЕ обязательное (по умолчанию "pending")

#### **Создание города:**
- `name` - **обязательно**
- ❌ `region`, `country` - НЕ обязательные поля

#### **Создание уведомления:**
- `userId`, `message`, `type` - **обязательны**
- ❌ `metadata` - НЕ обязательное поле

#### **Создание промокода:**
- `code`, `description`, `startDate`, `endDate`, `minOrderSum`, `discountType`, `discountValue`, `isActive`, `usageLimit` - **обязательны**
- ❌ `applicableProducts`, `applicablePoints` - НЕ обязательные поля

#### **Создание сессии:**
- `device_id` - **обязательно**
- ❌ `location` - НЕ обязательное поле

### Точки (Points)
- **GET /points** - получить все точки (без авторизации)
- **GET /points/1** - получить точку по ID
- **POST /points** - создать новую точку (требует авторизации)
- **PUT /points/1** - обновить точку (требует авторизации)
- **DELETE /points/1** - удалить точку (требует авторизации)

### Заказы (Orders)
- **GET /orders** - получить все заказы (требует авторизации)
- **GET /orders/1** - получить заказ по ID
- **POST /orders** - создать заказ
- **PUT /orders/1/status** - обновить статус заказа

### Кеш (Cache)
- **GET /cache/stats** - статистика кеша (без авторизации)
- **DELETE /cache/clear** - очистить кеш (требует авторизации)
- **GET /cache/get/key** - получить значение из кеша
- **POST /cache/set** - установить значение в кеш

## 🧪 Сценарии тестирования для курсовой

### Сценарий 1: Полный цикл работы с точками
1. **Регистрация** → получение токена
2. **GET /points** → просмотр всех точек
3. **POST /points** → создание новой точки
4. **GET /points/{id}** → просмотр созданной точки
5. **PUT /points/{id}** → обновление точки
6. **DELETE /points/{id}** → удаление точки

### Сценарий 2: Тестирование кеширования
1. **GET /cache/stats** → проверка статистики кеша
2. **GET /points** → запрос данных (должен закешироваться)
3. **GET /cache/stats** → проверка увеличения hit rate
4. **DELETE /cache/clear** → очистка кеша
5. **GET /cache/stats** → проверка очистки

### Сценарий 3: Работа с заказами
1. **Регистрация** → получение токена
2. **GET /products** → просмотр доступных продуктов
3. **POST /orders** → создание заказа
4. **GET /orders** → просмотр всех заказов
5. **PUT /orders/{id}/status** → изменение статуса заказа

## 📊 Анализ результатов

### Успешные ответы (200-299)
- **200 OK** - успешный запрос
- **201 Created** - ресурс создан
- **204 No Content** - успешное удаление

### Ошибки клиента (400-499)
- **400 Bad Request** - неверные данные
- **401 Unauthorized** - требуется авторизация
- **403 Forbidden** - недостаточно прав
- **404 Not Found** - ресурс не найден

### Ошибки сервера (500-599)
- **500 Internal Server Error** - внутренняя ошибка сервера

## 🔍 Полезные функции Postman

### 1. Автоматическое сохранение токена
В запросе "Регистрация пользователя" настроен скрипт, который автоматически сохраняет токен в переменную `{{token}}`.

### 2. Переменные окружения
Используйте `{{base_url}}` и `{{token}}` в запросах для удобства.

### 3. Тесты (Tests)
Добавьте тесты для проверки ответов:
```javascript
pm.test("Status code is 200", function () {
    pm.response.to.have.status(200);
});

pm.test("Response has required fields", function () {
    const jsonData = pm.response.json();
    pm.expect(jsonData).to.have.property('id');
});
```

### 4. Pre-request Scripts
Для автоматической генерации данных:
```javascript
pm.globals.set("randomEmail", "test" + Math.random() + "@example.com");
```

## 🚨 Частые проблемы

### 1. CORS ошибки
- Убедитесь, что backend запущен на порту 8080
- Проверьте, что все сервисы в docker-compose работают

### 2. Ошибки авторизации
- Проверьте, что токен сохранен в переменной `{{token}}`
- Убедитесь, что токен не истек

### 3. Ошибки валидации
- Проверьте формат данных в Body запроса
- Убедитесь, что все обязательные поля заполнены

## 📞 Поддержка

Если возникают проблемы:
1. Проверьте логи backend: `docker-compose logs backend`
2. Убедитесь, что все сервисы запущены: `docker-compose ps`
3. Проверьте доступность API: `curl http://localhost:8080/points`
